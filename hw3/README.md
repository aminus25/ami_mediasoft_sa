# Логическая ERD-модель "Сервис туроператоров, бронирования отелей и покупки билетов"

Логическая ERD-модель (логический уровень, нотация «вороньей лапки») для сервиса, в котором туроператоры публикуют туры, а пользователи бронируют туры, номера в отелях и билеты на транспорт.

## Связи между сущностями

| Связь | Тип | Описание |
|-------|-----|----------|
| User — Role | M:N (через `User_Role`) | У пользователя может быть несколько ролей |
| User — TourOperator | M:N (через `Operator_Manager`) | У оператора несколько менеджеров, пользователь может работать в нескольких компаниях |
| TourOperator — Tour | 1:N | Оператор публикует много туров |
| Tour — Hotel | M:N (через `Tour_Hotel`) | Тур включает несколько отелей |
| Tour — Transport | M:N (через `Tour_Transport`) | Тур включает несколько сегментов транспорта |
| Hotel — RoomType | 1:N | У отеля много типов номеров |
| RoomType — RoomInventory | 1:N | Доступность хранится по датам |
| Transport — Seat | 1:N | У рейса много мест |
| User — Booking | 1:N | Пользователь делает много броней |
| Booking — Tour | M:N (через `Booking_Tour`) | Бронь может включать туры |
| Booking — RoomType | M:N (через `Booking_Hotel`) | Бронь может включать номера |
| Booking — Seat | M:N (через `Booking_Ticket`) | Бронь может включать билеты |
| Booking — Payment | 1:N | У брони может быть несколько платежей (предоплата, доплата, возврат) |
| Booking — Passenger | 1:N | В брони может быть несколько пассажиров |
| Passenger — Booking_Ticket | 1:N | Пассажир может быть указан в нескольких билетах одной брони |
| Seat — Booking_Ticket | 1:1 в рамках активной брони | Билет ссылается ровно на одно место, место занято не более чем одним активным билетом |
